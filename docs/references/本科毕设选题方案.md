## 二、范式定位：把 Agent-Harness 搬进游戏

**本质**：本系统不是"做了一个 AI 游戏"，而是**搭了一个受约束的 Agent-Harness（脚手架 / 合法操作 shell）+ 一款游戏作为其观测与执行场**。模型只在平台给定的合法操作集合内自由组合、完成决策，安全由 harness 保证而非模型自觉——这与 Codex / Claude Code 的 agent-harness 范式同构。

| Codex / Claude Code | 本系统 |
|---|---|
| 工具 / tool schema | **合法原语**（`生成(ITEM)@(X,Y)`） |
| shell / harness 约束 | **组合语法 + 校验器**（循环 / 坐标 / 配额 / 守卫） |
| `run_command` 等工具调用 | **组合动作**经校验后执行 |
| 模型决定"调哪个工具、组合几步" | AI 决定"如何组合原语实现对抗 / 剧情" |

**安全叙事定位**：闭环的「非法零执行率」来自 harness（纯规则校验器），而非模型——与当前 **tool-calling 安全 / Agent 越权防护 / prompt-injection** 等热点同一战场，审稿人与读者能一眼看懂贡献点。

**一句话定位**：在 Unity 肉鸽游戏里搭一个受约束的 Agent-Harness——本地大模型只负责对话与陈述性回应，所有对游戏引擎的改动都来自「可组合的安全动作原语」，由 AI 自由组合、统一过纯规则校验器后执行；配合 decision-native 决策头在候选组合上打分选优。

**两个核心创新 + 一个系统**：
- **创新 A · 生成—选择分离**：LLM 从不直接发游戏命令，引擎只认「经校验的命令」→ **安全由构造 / harness 保证，不依赖模型对规则的自觉。**
- **创新 B · 可组合安全动作（受约束工具集）**：有限原语（`生成(ITEM)@(X,Y)`、`给予(buff)@(单位)`）× 受限组合语法（循环 / 坐标 / 每帧配额 / 互斥 / 条件守卫）× 组合校验器 → **有限合法组合生成无限行为** + 对抗式实时反馈。
- **系统实现**：本地对话模型 + 原语 / Harness 校验器 + decision-native 决策头（SemIf）构成的完整闭环。

**研究内容分解（四块）**：
1. **Harness 平台层**：合法原语集 + 受限组合语法（循环 / 坐标 / 配额 / 守卫）作为 Agent 的"合法操作 shell"。
2. **安全层**：纯规则组合校验器——注入越界 / 伪命令 / 无守卫组合 → **非法零执行率**（对标 Agent 安全 / 越权防护）。
3. **决策层**：decision-native 决策头（SemIf）在候选组合上打分选优。
4. **应用层**：全局观察 → 对抗 → 专属剧情 → 新鲜感嵌入 Unity 游戏闭环。

**主创新（一句话）**：把 **Agent-Harness 的安全范式**（合法 shell + harness 兜底）引入游戏引擎，让 AI"自由但必然合法"地组合出无限游戏行为。

**前置研究：开源 Agent-Harness 源码清单**（按对毕设有用的优先级排序；关键看"约束与安全怎么实现"，不是"怎么编排多智能体"）。

> **主蓝本分工（v1.3 定）**：**Pi 为主蓝本**（循环/工具/skill 全链条，代码小、可整套读透重写）；**DeepSeek Harness(dsh) 作安全层参考**（工具契约/沙箱/插件化）；**ZCode 看设计**（多工具/Plan mode）。

| 优先级 | 项目/对象 | 看什么（喂给毕设） |
|---|---|---|
| ★★★ 主蓝本 | **Pi（@earendil-works/pi-coding-agent）** | 极简可 fork：CLI→AgentSession→Agent→runAgentLoop（LLM→工具→再LLM）→ModelRuntime→Provider → 自研 harness 的循环骨架 |
| ★★★ 安全层参考 | **dsh（DeepSeek Harness, MIT）** | 工具契约 tool contracts、沙箱 sandbox、插件化内核 → 你的纯规则校验器/安全层设计 |

## 三、总体功能分层（把四个点挂到树上）

| 层级 | 对应概念 | 系统角色 | 本科工作量档 |
|---|---|---|---|
| **感知层** | 全局游戏观察 | 序列化游戏状态喂给 AI，作为意图编制的输入（AI"看得见"玩家在哪、买了什么、进了哪个房间） | **必做** |
| **内核（方法）** | 可组合安全原语 + 组合校验器（受约束工具 / Harness） | LLM 只能用它表达动作，过纯规则校验才执行 | **必做**（核心创新） |
| **行为层** | 对抗 | 把挑衅/押注翻译成原语组合（如"不买→进房刷 100 火焰符"），是对抗型组合触发 | **必做**（≥1 个触发器） |
| **生成层** | 专属剧情回应 | LLM 生成因人/因局势而异的纯文本剧情与对话（唯一自由发挥处，不动游戏） | **加分** |
| **效果目标** | 玩家新鲜感 | 评测维度：游戏 AI 是否持续带来惊喜 | **可裁剪**（问卷/行为统计） |

**一句话收口**：全局观察让 AI"看得见你"，内核让 AI"能合法表达动作"，对抗是"对看得见的你回击"，专属剧情是"对看得见的你讲专属的话"，新鲜感是"叠加后你是否持续觉得好玩"。

## 五、研究内容分解（含工作量档）

**必做（决定能否毕业）**
1. 对话/回应由 LLM 完成，且 LLM 无任何直接改游戏能力。
2. 定义 3–5 个合法原语；实现组合语法 + 纯规则校验器。
3. `循环生成` / `条件触发` 各至少一个可运行的组合。
4. 端到端闭环跑通 + 界面反馈。

**建议（加分）**
5. decision-native 决策头（SemIf）在候选组合上打分（可先做 top-1 简单版）。
6. 至少 1 个对抗触发器 + 少量专属剧情变体。

**可裁剪（有余力再做）**
7. 完整对抗脚本库 / 玩家问卷 / 多模型对比。

## 六、答辩必答的量化点（提前做成表）

1. **注入鲁棒性（关键卖点）**：故意让 LLM 输出越界 / 伪命令 / 无守卫组合 → 展示「非法零执行率」，证明安全由校验器保证而非模型自觉。
2. **组合表达力**：N 个原语在组合语法下可生成的行为数 vs 纯枚举动作数，突出"有限原语 → 无限变化"。
3. **端到端演示**：玩家挑衅 → AI 组合对抗 → 引擎实时反馈的录屏/现场演示。

## 九、风险与规避

- **风险：动作越界 / 伪命令** → 校验器纯规则兜底 + 注入测试（非法零执行）。
- **风险：显存不足** → 策略头 sidecar（Qwen3.5-4B nf4）与对话模型分时/顺序加载，或降级用对话模型自带打分。
- **风险：工作量失控** → 严格按「必做优先」裁剪，加分项留白；答辩重演示完整闭环。
- **风险：答辩被质疑"AI 会不会乱来"** → 用"生成—选择分离 + 构造保证合法"路线正面回应。
